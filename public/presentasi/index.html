Bagian 1 — Klasifikasi Akses

Penjelasan Peran Pengguna (User Roles)

Aplikasi BrightDor dirancang dengan pembagian hak akses (Role-Based Access Control) yang ketat. Masing-masing tipe pengguna memiliki dashboard, alur kerja, dan kewenangan transaksi yang saling melengkapi.

End-User / Customer

Couple (Calon Pengantin)

Pengguna publik pencari jasa pernikahan. Bertindak sebagai pemesan paket, pengaju penawaran anggaran, dan pemberi ulasan resmi pasca-acara.

  • Eksplorasi vendor berdasarkan kota & kategori
  • Reservasi tanggal langsung (Booking Form)
  • Negosiasi harga khusus via Penawaran (Offer Modal)
  • Pelacakan status transaksi di dashboard Booking Saya
  • Pemberian rating & ulasan terverifikasi
  • Reset kata sandi mandiri (Self-Service)
Mitra Penyedia Jasa

Vendor (Mitra Bisnis)

Pelaku usaha industri pernikahan (Fotografer, Venue, MUA, Catering, dll). Memiliki panel khusus berbasis Filament untuk mengelola etalase bisnis.

  • Manajemen profil bisnis, media portofolio & logo
  • Katalog paket layanan (harga, diskon, kapasitas, fasilitas)
  • Konfirmasi dan pengelolaan status pesanan masuk
  • Pengajuan pencairan saldo pendapatan (Payout)
  • Unggah dokumen legalitas untuk badge verifikasi
Platform Superuser

Admin (Pengelola Sistem)

Superuser pengendali operasional BrightDor. Mengawasi kepatuhan transaksi, moderasi profil vendor, verifikasi pembayaran manual, dan keamanan data.

  • Validasi pembayaran otomatis & semi-otomatis
  • Moderasi kelayakan vendor & kurasi vendor unggulan
  • Pengawasan transaksi global & pemotongan komisi platform
  • Pemeriksaan riwayat audit keamanan (Audit Logs)
  • Otoritas data tanpa campur tangan password user

Bagian 3 — Kendali Platform

Dashboard Admin (Filament v5)

Pusat pengelolaan terpadu yang dirancang untuk menangani beban operasional tinggi dengan otomatisasi cerdas, validasi pembayaran terintegrasi, dan keamanan berlapis.

Pilar 1 — Pembayaran

Validasi Pembayaran Semi-Auto

Transaksi dari gateway pembayaran (Midtrans/Xendit) tervalidasi otomatis melalui webhook callback server-to-server. Namun untuk pembayaran transfer manual, admin memiliki antarmuka khusus untuk mencocokkan bukti mutasi rekening secara cepat sebelum mengubah status menjadi lunas.

Pilar 2 — Skalabilitas Operasional

Manajemen Menu Terstruktur

Ketika data bisnis bertumbuh dengan puluhan menu (Users, Vendors, Services, Bookings, Transactions, Testimonials, Settings), arsitektur Filament mengelompokkannya ke dalam klaster navigasi (Master, Marketplace, Keuangan, Konten) lengkap dengan fitur pencarian global (Ctrl+K) agar admin tidak kewalahan.

Pilar 3 — Otomatisasi Sistem

Otomatis Tervalidasi Sendiri

Komputasi komisi platform (contoh: 10% default), akumulasi rating vendor saat review baru masuk, pembaruan agregasi ulasan, dan pergantian status langganan vendor (subscription active vs expired) dieksekusi secara otomatis oleh background event listener tanpa memerlukan intervensi manual admin.

Bagian 5 — Infrastruktur & Standar Operasional

Keamanan Pengguna & Efisiensi Hosting

Prinsip arsitektur teknis BrightDor mengedepankan efisiensi biaya infrastruktur pada tahap awal (tidak boros resource) sembari mempertahankan standar keamanan data enterprise yang kokoh.

Enkripsi Kata Sandi Bcrypt

Semua password pengguna di-hash satu arah menggunakan algoritma Bcrypt (work factor 12) dengan salt dinamis. Teks asli kata sandi tidak pernah disimpan dan bahkan admin superuser tidak memiliki kemampuan untuk membacanya.

Lupa Password Mandiri (Anti-Social Engineering)

Sesuai standar operasional: Admin tidak mengubah password user. Pengguna yang lupa kredensial mereset sendiri via email token berbatas waktu untuk mencegah penipuan manipulasi identitas (social engineering).

Audit Logging Terstruktur

Setiap aksi krusial sistem (persetujuan dokumen vendor, perubahan nominal harga paket, transaksi pembayaran, pencairan saldo payout) dicatat ke tabel audit_logs lengkap dengan metadata IP address, user-agent, nilai lama, dan nilai baru.

Proteksi Otomatis CSRF & XSS

Laravel menyisipkan verifikasi CSRF token di setiap request formulir guna menangkal pemalsuan permintaan antar-situs, serta menerapkan context-aware HTML escaping otomatis pada Blade template engine untuk membendung injeksi skrip XSS.

Strategi Hosting Database Efisien

Sesuai arahan: "Ketika hosting databasenya tidak sampai banyak dan sesuai standar dan kebutuhannya". Database MySQL dikonfigurasi dengan indexing tepat dan normalisasi relasional terukur sehingga berjalan ringan tanpa membebani biaya server pada tahap awal rilis.

Skalabilitas Domain & Upgrade Infrastruktur

Sesuai arahan: "Ketika domain lemah harus di-upgrade kembali". Arsitektur aplikasi decoupling (stateless web + media symlink terpisah) siap dipindahkan secara mulus dari shared hosting awal ke VPS performa tinggi atau cloud container (DigitalOcean/AWS) saat lonjakan trafik pengguna terjadi.

Katalog Rinci 7 Modul & Penjelasan Relasi Database

Rincian struktur kolom kunci, tipe data, dan aturan keterkaitan antar tabel untuk menjawab pertanyaan teknis dosen.

1. Modul Autentikasi & Pengguna (Users & RBAC)

Pondasi keamanan akses untuk memisahkan hak login admin, mitra vendor, dan calon pengantin (couple).

Tabel: users, password_reset_tokens, sessions, roles, permissions, model_has_roles, model_has_permissions, role_has_permissions
• users: PK id, email (unique), password (bcrypt hash), user_type (admin/vendor/couple), status, field langganan vendor (vendor_subscription_status, vendor_subscription_expires_at).
• password_reset_tokens: PK email, token acak SHA-256 untuk reset mandiri.
• Relasi: 1 User terhubung ke 1 Vendor (unique), atau 1 User terhubung ke banyak Bookings.

2. Modul Sistem Mitra Vendor & Layanan

Entitas profil bisnis penyedia jasa pernikahan, katalog kategori, paket harga, dan berkas verifikasi resmi.

Tabel: vendors, vendor_categories, services, vendor_documents
• vendors: PK id, FK user_id (unique 1:1), FK vendor_category_id, business_name, slug, city, rating_avg, status (pending/approved/rejected), is_verified.
• services: PK id, FK vendor_id (1:N), name, price, discount_price, capacity, duration, features (JSON).
• vendor_documents: PK id, FK vendor_id, dokumen KTP/NIB/sertifikasi untuk ditelaah admin.

3. Modul Pemesanan (Booking) & Ulasan (Review)

Inti transaksi operasional jasa pernikahan antara calon pengantin dengan vendor terpilih.

Tabel: bookings, reviews
• bookings: PK id, booking_code (unik cth. BD-XXXXX), FK user_id → users, FK vendor_id → vendors, FK service_id → services, event_date, guest_count, total_amount, status (pending/confirmed/on_progress/completed/cancelled).
• reviews: PK id, FK booking_id (unique per booking), FK vendor_id, FK user_id, rating (1-5), content. Otomatis memicu kalkulasi ulang rating_avg pada vendor.

4. Modul Undangan Digital (Invitations)

Fitur add-on penciptaan undangan pernikahan berbasis web dengan domain khusus dan sistem RSVP kehadiran tamu.

Tabel: invitation_templates, invitation_template_categories, invitation_orders, invitations, invitation_rsvps
• invitations: PK id, FK invitation_order_id, slug, subdomain, content (JSON susunan acara, galeri, musik), counter views_count, rsvp_yes/no/maybe.
• invitation_rsvps: PK id, FK invitation_id, guest_name, attendance, guest_count, message ucapan selamat.

5. Modul Transaksi Finansial & Payout Mitra

Pencatatan mutasi pembayaran serbaguna dan mekanisme pencairan penghasilan vendor.

Tabel: transactions, commission_settings, payouts
• transactions: PK id, transaction_code, FK user_id, payable_type & payable_id (polimorfik ke Booking atau InvitationOrder), amount, payment_gateway (Midtrans/Xendit/Manual), status (pending/success/failed).
• payouts: PK id, payout_code, FK vendor_id, amount, net_amount, status pencairan, FK processed_by → users (admin pemroses).

6. Modul Manajemen Konten (CMS)

Pengelolaan materi informasi publik beranda untuk membangun kepercayaan dan panduan calon pengantin.

Tabel: blogs, banners, testimonials, faqs, galleries
• blogs: Artikel inspirasi pernikahan (FK user_id penulis, title, slug, content, status).
• banners & testimonials: Banner promosi hero serta testimoni nyata pengantin untuk meningkatkan kredibilitas platform.

7. Modul Media Spatie & Sistem Internal

Penyimpanan aset media polimorfik, audit forensik keamanan, notifikasi sistem, dan queue engine.

Tabel: media, audit_logs, notifications, settings, jobs, failed_jobs, job_batches, cache, cache_locks
• media: Spatie Media Library polimorfik (model_type, model_id, collection_name: logo, portfolio, documents, cover). Mendukung konversi thumbnail otomatis.
• audit_logs: FK user_id, action, model, old_values & new_values (JSON snapshot data sebelum vs sesudah perubahan), ip_address forensik.
• notifications: UUID PK, notifikasi event booking dan approval ke akun pengguna.
